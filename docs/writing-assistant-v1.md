# 编辑器写作助手 v1

[inkwell#8](https://github.com/raychi-space/inkwell/issues/8) · [raychi#13](https://github.com/raychi-space/raychi/issues/13) · [服务契约](https://github.com/raychi-space/wellspring/blob/main/docs/api/writing-agent-v1.md)

## 使用

侧栏“助手管理”新增 OpenAI-compatible 服务商（API 地址为 `/chat/completions` 前缀），填写实际模型 ID、密钥后保存；分别测试聊天连接与工具能力。编辑时密钥留空/保留不覆盖原值，设置/替换与清除是明确动作。助手可编辑提示词、固定背景、模型与上下文/超时/输出预算。配置保存在内核服务，页面不持有查询到的明文密钥。

文章的 MDXEditor 右侧显示可收起助手，保留内容信息。普通发送是建议对话；每轮任务使用最新未保存正文，带最近完整对话和建议的确认状态。页面刷新、收起面板、切换文章后对话重新开始；晚到任务无法应用到新页面。一次只允许一个在途任务或待确认建议，任务状态每秒查询。服务失败时现有编辑内容保留。

## 选区支持与确认

先在正文选择文字，再点击“交给助手”保存选区，右侧描述要求并点击“修改选区”。该动作通过 MDXEditor 的公开 realmPlugin/rootEditor$ 注册 Lexical 根编辑器，并在同一同步读取中保存 RangeSelection 克隆、原文文本与公开 getSelectionMarkdown 的 Markdown。

第一期支持**根编辑器的无格式文字段落，以及这些段落中的连续选区**。两个端点必须是 TextNode。选中的段落不能带粗体、斜体、链接、内联代码或换行节点；标题、列表、引用、表格、图片、代码块和嵌套编辑器暂不支持，界面明确提示。没有富文本到 Markdown 偏移换算，也不查找首个匹配字符串。接受时按节点 key/offset 书签检查有效性与原文，恢复选区，通过公开 insertMarkdown$ 导入新 Markdown，在同一次带 HISTORY_PUSH_TAG 的 Lexical 更新中替换。新内容支持已安装插件的 Markdown 导入；空字符串明确显示“删除选区”。相同 Markdown 显示“没有修改”。

提交修改到接受、拒绝或失败期间正文只读、工具栏不可操作、保存/发布禁用。红色原文与绿色新文用独立 React portal 展示在段落附近，越靠近底部会限制预览高度，允许滚动操作按钮。预览不插入 Lexical，不参与 Markdown 或草稿保存。

接受只消耗一次书签，形成独立撤销记录，正常 onChange 标记工作稿。拒绝只是释放书签，从未修改正文。书签失效、原文变化或编辑器重挂载时报“原文已变化，请重新选择”，不自动合并。保存与发布仍需站主明确操作；生成或接受不会发布。

## 摘要、历史与故障

“生成摘要”读取浏览器完整未保存 Markdown、标题和现有摘要；应用摘要才更改本地字段。正文、标题或摘要改变后候选标记过期并禁用应用，需重新生成；关闭不改变原摘要。

下一轮重新捕获最新上下文，助手记录附已接受/拒绝/过期状态，历史工具调用不会重新执行。历史存本页状态，Provider/Assistant/任务在服务端持久。选择新助手不会恢复旧会话。

网络失败可“重试本次提交”，复用整个原请求与 requestId，避免重复模型任务。任务已失败后重新点击发送/修改/摘要会用新 ID，表示主动重新生成。过期选区不能用网络重试重新应用。超时、非法结果、上下文超限等展示后端可读原因并保持正文。

## 验证与启动

`npm ci --ignore-scripts && npm run build`。开发模式 `?editor-agent-fixture=1` 提供无后端/模型的固定替换验证页（生产不可进入），检查重复文字、捕获后焦点切换、接受、拒绝、Markdown 导出与撤销。后端配置独立 Agent 服务后用真实管理台任务接口联调；本期模拟模型验收和截图见 raychi 主 Issue，真实模型由用户随后配置。

实现使用 MDXEditor4.3.0 与 Lexical0.48.0 的公开 API；依赖 Lexical 显式锁定同版本。帖子目前使用普通 textarea，本期助手仅接入文章 MDXEditor，复杂节点和帖子编辑助手为后续范围。
